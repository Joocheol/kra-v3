# tfoot 매출액 누락 진단

결론부터: **`_sales_and_notice` 도 `parse_tables` 도 아무것도 잃지 않는다.**
Scm 페이지의 `<tfoot>` 원문에는 애초에 매출액이 넷뿐이다. 나머지 네 승식
(쌍승·복연승·삼복승·삼쌍승)의 매출액은 Scm 이 아니라 형제 페이지
(`Both`, `Bc`, `3Bc`, `3Both`)의 `<tfoot>` 에 각각 따로 들어 있다.

검증 대상 예시: `2024-06-01_1_05`
(`~/Dropbox/kra-analysis/data/raw_collected_v3_15w/kra_2024/raw_archive/2024/2024-06/2024-06-01_1_05.json.gz`)

---

## 2. 원문에 실제로 몇 개의 매출액이 있는가

Scm tfoot 원문 안의 실측:

| 항목 | 개수 |
| --- | --- |
| 콜론(`:`)을 포함한 셀 | **4개** |
| `<tr>` | 2개 |
| `rowspan` | 0개 (없음) |
| `colspan` | 6개 — `4,4,4,5`(1행) / `4,13`(2행) |

콜론 셀 4개의 라벨과 값:

| 라벨 | 값 |
| --- | --- |
| 단승식 | 33,279,700원 |
| 연승식 | 54,514,400원 |
| 복승식 | 915,036,500원 |
| 총매출액 | 2,766,400,200원 |

문자열 등장 횟수 (Scm tfoot 원문 안):

| 문자열 | 횟수 |
| --- | --- |
| `합` | **0** |
| `총` | 1 (`총매출액`) |
| `단승` | 1 |
| `연승` | 1 |
| `복승` | 1 |
| `쌍승` | **0** |
| `복연승` | **0** |
| `삼복승` | **0** |
| `삼쌍승` | **0** |

즉 캡처 화면의 일곱 승식 + "합 계" 중 Scm tfoot 에 존재하는 것은
단승식·연승식·복승식 셋과, "합 계"에 해당하는 `총매출액` 하나뿐이다.
`쌍승`, `복연승`, `삼복승`, `삼쌍승` 이라는 글자는 tfoot 원문에 **한 번도**
나오지 않는다. 파싱 이전 단계에서 이미 없다.

Scm 표 자체의 `<caption>` 도 이를 말한다:

```html
<caption>출전번호별 단,연,복승식의 배당률, 매출총액, 취소마를 제공하는 표</caption>
```

## 3. 나머지 넷은 어디 있는가 — 형제 페이지의 tfoot

같은 아카이브 파일의 다른 페이지 tfoot (공백 정리해 한 줄로):

```html
<!-- Both -->
<tfoot> <tr> <th class="firstChild" colspan="4">쌍승식 매출총액</th>
  <th class="dataLeft" colspan="11"> 289,737,000원</th> </tr>
  <tr> <th class="firstChild" colspan="4">취소마공지</th>
  <th colspan="11"> 취소마가 없습니다. </th> </tr> </tfoot>

<!-- Bc -->
<tfoot> <tr> <th class="firstChild" colspan="4">복연승식 매출총액</th>
  <th class="dataLeft" colspan="11"> 109,954,000원</th> </tr> ... </tfoot>

<!-- 3Bc/1 -->
<tfoot> <tr> <th class="firstChild" colspan="4">삼복승식 매출총액</th>
  <th class="dataLeft" colspan="11"> 916,133,800원</th> </tr> ... </tfoot>

<!-- 3Both/1 -->
<tfoot> <tr> <th class="firstChild" colspan="4">삼쌍승식 매출총액</th>
  <th class="dataLeft" colspan="11"> 447,744,800원</th> </tr> ... </tfoot>

일곱 승식을 모으면 Scm 의 `총매출액` 과 정확히 일치한다 (원 단위까지):

  쌍승식     289,737,000
  복연승식   109,954,000
  삼복승식   916,133,800
  삼쌍승식   447,744,800
  ----------------------
  합계     2,766,400,200   == Scm 총매출액 2,766,400,200  ✔
```

## 4. `parse_tables` 결과와 원문 대조

`kra/htmltable.py` 의 `parse_tables` → `table.section("foot")`, Scm.
`n_rows=2, n_cols=17`. `spanned=False` 인 실셀만 옮기면:

| r | col | colspan | text |
| --- | --- | --- | --- |
| 0 | 0 | 4 | `단승식 : 33,279,700원` |
| 0 | 4 | 4 | `연승식 : 54,514,400원` |
| 0 | 8 | 4 | `복승식 : 915,036,500원` |
| 0 | 12 | 5 | `총매출액 : 2,766,400,200원` |
| 1 | 0 | 4 | `취소마공지` |
| 1 | 4 | 13 | `취소마가 없습니다.` |

(나머지 좌표는 전부 `spanned=True` 인 그림자 셀 — colspan 이 만든 복제본이다.)

원문 4개 : 파싱 4개. **일치. 손실 0.**

`_sales_and_notice(table)` 반환값:

```python
({'단승식': '33,279,700원',
  '연승식': '54,514,400원',
  '복승식': '915,036,500원',
  '총매출액': '2,766,400,200원'},
 '취소마가 없습니다.')
```

원문에 있는 것을 전부 잡았다. 라벨의 개행·들여쓰기(`단승식 :\n\n ... 33,279,700원`)는
`htmltable.normalize`(`kra/htmltable.py:32`)가 공백 런을 하나로 접어 이미
해결하고 있고, spanned 셀은 `kra/race.py:197` 의
`[c for c in foot.row(r) if not c.spanned]` 에서 걸러진다.

## 5. 코드 줄 단위 — 정확히 어디서 넷으로 끝나는가

넷만 나오는 이유는 파싱 실패가 아니라 **호출 지점의 페이지 선택**이다.

- `kra/race.py:282` — `race.sales, race.cancel_notice = _sales_and_notice(table)`
  이 줄은 `page_key == "Scm"` 인 분기 안에서만 실행된다. 매출액을 읽는 대상이
  Scm 한 페이지로 고정되어 있고, Scm 원문에는 넷밖에 없다. 따라서 결과도 넷이다.

- `kra/race.py:203` — `if ":" in t:` 는 "라벨과 금액이 한 셀 안에 콜론으로
  이어져 있다"는 Scm 전용 형식을 전제한다. 형제 페이지의 tfoot 은 형식이 달라서
  `쌍승식 매출총액` 과 `289,737,000원` 이 **서로 다른 셀**로 나뉘어 있고 콜론이
  없다. 그래서 설령 같은 함수에 `Both`/`Bc`/`3Bc`/`3Both` 테이블을 넘겨도
  `sales` 는 `{}` 로 나온다. 실제로 확인했다:

  ```
  _sales_and_notice(Both  테이블) -> ({}, '취소마가 없습니다.')
  _sales_and_notice(Bc    테이블) -> ({}, '취소마가 없습니다.')
  ```

  (`취소마공지` 는 `kra/race.py:199` 의 `startswith(CANCEL_NOTICE)` 로 잡히므로
  notice 만 채워진다.)

정리하면 "놓치는 지점"은 두 겹이다.
(a) 282줄 — 넷뿐인 페이지 하나만 본다.
(b) 203줄 — 나머지 넷이 있는 페이지들의 tfoot 형식(라벨/금액 분리, 콜론 없음)을
읽을 수 없다.

spanned 처리(197줄), 콜론 partition 위치(204줄), 라벨 공백/개행(normalize)은
전부 정상이며 이번 누락의 원인이 아니다.

## 7. 캡처 화면과의 차이

캡처의 목록은 일곱 승식이 나란히 있고 마지막이 "합 계"다. Scm 은 셋 + `총매출액`
이고 "합"이라는 글자가 없다. 라벨 문자열부터 다르므로, 캡처는 Scm 페이지의
tfoot 이 아니라 승식별 매출을 한데 모아 보여 주는 다른 화면이다. 그 화면에
해당하는 HTML 은 이 아카이브의 `pages` 다섯 키 어디에도 없다 — 다만 그 숫자
자체는 위 3절처럼 다섯 페이지의 tfoot 에 흩어져 전부 보존되어 있다.
