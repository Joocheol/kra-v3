## 판정 기준 — 실제로 쓴 코드

```python
POOLS = ["단승식", "연승식", "복승식", "쌍승식", "복연승식", "삼복승식", "삼쌍승식"]
TOTAL = "총매출액"
EXPECTED = POOLS + [TOTAL]                       # 여덟 라벨

def to_int(s):                                   # "33,279,700원" -> 33279700
    d = re.sub(r"[^\d]", "", s or "")
    return int(d) if d else None

miss = [k for k in EXPECTED if k not in race.sales]              # 1. 라벨 누락
sum(to_int(race.sales[k]) for k in POOLS) != to_int(race.sales[TOTAL])   # 2. 합계 불일치
[p for p in race.problems if "매출액 불일치" in p]                 # 3. 고정마 불일치
```

## 1. 일곱 승식이 항상 다 잡히는가 — 그렇다

19,301 경주 **전부**에서 `race.sales` 의 키가 정확히 여덟 개였다:

```
단승식, 연승식, 복승식, 쌍승식, 복연승식, 삼복승식, 삼쌍승식, 총매출액
```

- 한 라벨이라도 빠진 경주: **0건**
- 여덟 개 밖의 라벨이 섞여 들어온 경주: **0건** (`labels_extra` 가 빈 dict)

즉 라벨 집합이 19,301번 모두 동일했다. 연도·경마장·경주번호에 따라 달라지는
경우가 없다.

## 2. 일곱 승식의 합이 총매출액과 맞는가 — 항상 맞는다

라벨 누락이 0건이므로 합계 검사는 19,301 경주 **전부**에서 실제로 수행됐다
(값이 없어 건너뛴 경주가 없다).

- 원 단위까지 `단승+연승+복승+쌍승+복연승+삼복승+삼쌍승 == 총매출액` 인 경주:
  **19,301 / 19,301**
- 어긋난 경주: **0건**

`findings/tfoot_diagnosis.md` 에서 손으로 확인했던 한 경주의 성질
(일곱 승식 합 == Scm 페이지의 총매출액) 이 아카이브 전체에서 예외 없이
성립한다. 이 등식은 다섯 페이지에서 서로 독립적으로 읽어 온 여덟 개 숫자가
맞물려야만 성립하므로, 수집·라벨링·금액 파싱이 전부 옳았다는 뜻이다.

## 3. `race.problems` 의 "매출액 불일치" — 0건

3Bc / 3Both 는 고정마별 변형 페이지 (`chulNo1=1..N`) 마다 같은 승식 총액을
반복해서 싣는다. 수정된 `parse_race` 는 같은 라벨이 다른 값으로 다시 들어오면
덮어쓰지 않고 `"매출액 불일치 {label} {prior} vs {amount}"` 를 `problems` 에
남긴다.

- 그런 문제가 기록된 경주: **0건**

변형 페이지 수는 출전 두수만큼이므로 (보통 8~16개) 경주당 삼복승식·삼쌍승식
값이 각각 여러 번 읽힌다. 그 반복이 19,301 경주 전부에서 한 번도 어긋나지
않았다.

## 검사가 헛돌지 않았다는 확인

0건이 "검사가 아무것도 보지 않아서 0"인 경우를 배제하기 위해, 수정 이전
동작(= Scm 페이지에서만 매출액을 모으는 것)을 같은 데이터에 시뮬레이션해
같은 판정 기준을 적용했다. 2024-03 의 앞 다섯 경주:

## 결론

수정된 파서는 아카이브 19,301 경주 전부에서 일곱 승식 + 총매출액 여덟 라벨을
빠짐없이 모으고, 그 합이 총매출액과 원 단위까지 일치하며, 고정마 변형 간
값 충돌도 한 건도 없다. 세 판정 모두 0건.
