# SPEC_P0 — 데이터 검증

> r1 비평 K1–K7 반영본. 변경 사유는 9절 정정 기록과
> `review/RESPONSE_P0_r1.md`에 있다.

## 0. 이 단계의 목적

원시 아카이브에서 분석 가능한 표를 만들고, **그 표가 맞다는 것을 원본 없이
어떻게 아는지**를 확립한다.

두 번째가 핵심이다. 아카이브는 수집기 v3의 산출물이고, 그 이전 단계는 존재하지
않는다(OPEN_ITEMS #1). KRA 페이지 원문과의 일치는 재수집으로만 확인할 수 있다.

## 1. 확정된 전제

2026-08-11에 실물로 확인한 것들.

| 항목 | 확인 내용 | 확인 방법 |
|---|---|---|
| 위치 | `<Dropbox>/kra-analysis/data/raw_collected_v3_15w/` | 전수 조회 |
| 구조 | `kra_YYYY/raw_archive/YYYY/YYYY-MM/YYYY-MM-DD_{meet}_{race}.json.gz` | 전수 조회 |
| 연도 | 2016–2019, 2022–2025 (2020–21 부재) | 폴더 목록 |
| 원문 | HTML 온전. `<!doctype html>`, `<table>` 존재 | `gunzip` 후 태그 계수 |
| 인코딩 | `<meta charset="euc-kr">` | 동일 |
| meet | 서울 1, 제주 2, 부산경남 3 | KRA 사이트 메뉴 |
| 페이지 | `Scm` `Both` `Bc` `3Bc`(마번별) `3Both`(마번별) | 파일 구조 |
| URL | 각 페이지의 원본 URL이 `urls`에 보존 | 파일 구조 |

`_probe`에 대해서는 4.1 IC-0 참조. **경주 한 건에서만 확인된 관찰이므로
전제가 아니다.**

### 1.1 풀과 페이지의 대응

| 페이지 | 담긴 풀 | 표 형태 |
|---|---|---|
| `Scm` | 단승 · 연승 · 복승 | 단승/연승 열 + 마번 열 + 복승 상삼각 |
| `Bc` | 복연승 | 대칭 행렬 (상삼각만 유효) |
| `Both` | 쌍승 | 비대칭 행렬. **헤더 `(후착 / 선착)` → 행=2착, 열=1착** |
| `3Bc` × 마번 | 삼복승 | 고정마 1 + 행/열 |
| `3Both` × 마번 | 삼쌍승 | **헤더 `(3위 / 2위)` → 행=3착, 열=2착** |

## 2. 설계 원칙 — 파서는 판정하지 않는다

v1·v4 파서의 실패 8건 중 대부분이 파생 필드였다. 배당률 숫자를 읽는 부분은
멀쥰했고, 틀린 것은 전부 파서가 규칙으로 계산해낸 값이었다.

| 층 | 산출물 | 하는 일 |
|---|---|---|
| L1 추출 | `raw_cells/` | HTML → 셀 값. **원문 그대로.** 판정 없음 |
| L2 규칙 | `derived/` | 도착순서 + 규정 → 적중, 지급 착순 수 |
| L3 진단 | `diagnostics/` | 검열, 이상 토큰, 정합성 위반 |

L1에 들어가서는 안 되는 필드: `is_hit`, `place_cutoff`, `is_capped`,
`is_valid`, `is_cancel`.

### 2.1 L1 스키마 — 좌표를 보존한다 (K3)

값 문자열만 보존하는 것으로는 무손실이 아니다. 행/열 매핑이 틀렸을 때 L1을
다시 돌려야 하기 때문이다. **셀의 출처 좌표를 함께 저장한다.**

`raw_cells/` 한 행 = 페이지의 한 셀.

| 컬럼 | 형 | 내용 |
|---|---|---|
| `race_id` | str | `YYYY-MM-DD_{meet}_{race}` |
| `page_key` | str | `Scm` `Both` `Bc` `3Bc` `3Both` |
| `page_variant` | str | 고정마 번호 또는 `_probe`. 단일 페이지는 빈 문자열 |
| `table_ord` | int | 페이지 내 표의 등장 순서 |
| `table_caption` | str | 표 캐션 원문 (표 식별의 근거) |
| `row_ord` | int | 표 내 행 순서 (0부터) |
| `col_ord` | int | 표 내 열 순서 (0부터) |
| `row_header` | str | 행 머리 셀의 원문 |
| `col_header` | str | 열 머리 셀의 원문 |
| `cell_raw` | str | **셀 원문 그대로.** 변환·정규화 없음 |
| `rowspan` `colspan` | int | 병합 셀 정보 |

`cell_raw`는 `9999.9`, `-`, `----`, `1.5 취소` 무엇이든 원문 그대로다. 숫자
변환은 L2·L3의 일이다.

이 스키마면 행/열 해석이 틀렸을 때 `row_ord`/`col_ord`만 다시 매핑하면 되고,
HTML을 다시 읽지 않는다.

### 2.2 필드 계보 (K2)

**모든 산출 필드는 계보표에 한 행을 갖는다.** 계보표가 없는 필드는 산출물에
존재할 수 없다.

| 컬럼 | 내용 |
|---|---|
| `field` | 필드명 |
| `layer` | L1 / L2 / L3 |
| `origin` | `direct`(원천 직접 판독) 또는 `derived`(규칙 계산) |
| `source` | direct면 원문 좌표, derived면 입력 필드 목록 |
| `rule` | derived면 생성식 |
| `warrant` | 그 규칙이 참인 근거: `규정` / `문서` / `측정` / **`없음`** |

`warrant`가 `없음`인 파생 필드는 **동결 조건 위반**이다. `outputs/p0/lineage.csv`로
산출하고 `REPORT_P0.md`에 요약한다.

L2의 핵심 파생 필드 — 지급 착순 수, 적중 여부 — 의 생성식은 **P0에서 확정하지
않는다.** 오버라운드 역산의 정확한 형태와 근거는 별도 명세를 요구하며, P0의
산출물은 그 규칙을 적용할 수 있는 `derived/` 자리와 계보표 골격까지다.
규칙 자체는 SPEC_P0b로 분리하고, 그 전까지 L2 필드는 `warrant=없음`으로
표시된 채 남는다. **이 상태로는 P0가 종료되지 않는다.**

## 3. 파서 규칙 — 세 버전 대조

### 3.1 v1이 틀렸고 v4가 고친 것

| 규칙 | v1 | v4 | v3 |
|---|---|---|---|
| 지급 착순 수 | 유효두수 ≥8→3, ≥5→2 | 부분식별 `[lo,hi]` | L2. 규칙은 SPEC_P0b |
| 복연승 적중 | 상위 `cutoff` 부분집합 | 항상 상위 3 | L2. 규칙은 SPEC_P0b |
| 검열 | `odds >= 9999.9` | `at_cap` / `above_cap` | L3. L1은 원문 보존 |
| 유효두수 | 단승 배당 있는 마번 | 등록두수 별도 보존 | L1이 마번 열 전체 보존 |
| 의존성 실패 | 맨몸 `except` | `import lxml` 최상단 | 동일 + IC-5 |

### 3.2 v4에 남은 것

**(a) `to_odds`의 느슨한 폴백.** v4는 이상 토큰을 기록하되 `re.search`로
숫자를 뽑아낸다. `"1.5 취소"`가 `1.5`가 된다. v3은 L1에서 아예 변환하지
않으므로 이 문제가 발생하지 않는다. 변환은 L3에서 하고, 정확히 매칭되지
않으면 `None` + `cell_raw` 보존.

**(b) `tables[0]`.** v3은 `table_caption`으로 표를 식별한다. 캐션은
`출전번호별 ...의 배당률, 매출총액, 취소마를 제공하는 표` 형태이며 `...`이
풀을 지정한다. 기대 캐션이 없으면 IC-5 실패.

**(c) `_probe`.** 4.1 IC-0 참조.

## 4. 검증

파서가 맞는지를 원본 없이 판단해야 하므로, 서로 다른 경로를 쓴다. **독립성의
정도가 다르며, 그 차이를 명시한다.**

### 4.1 내부 정합성 (전 경주)

각 검사는 **검정 대상 T**, **검정 기준 B**, **실패 가능 조건**을 함께 적는다.
B의 계산에 T 또는 T를 만든 규칙이 들어가면 순환이며 삭제 대상이다.

| ID | T | B | 실패 조건 | 무엇을 배제하는가 |
|---|---|---|---|---|
| IC-0 | `_probe` 파싱 결과 | `"1"` 파싱 결과 | 두 결과가 다를 때 | **비결정성과 위치 의존성만.** 정확성은 배제하지 못함 |
| IC-1 | 복승 행렬의 대각·하삼각 패턴 | 표 형태 규정 | 행/열 정렬이 어긋날 때 | 행/열 전치 |
| IC-2 | 삼복승 조합의 페이지 간 값 | 서로 다른 고정마 페이지의 같은 조합 | 값이 불일치할 때 | 셀 매핑 오류 |
| IC-3 | 도착마번 집합 | 등록 마번 집합 | 부분집합이 아니거나 중복일 때 | 마번 추출 오류 |
| IC-4 | 각 풀의 관측 조합 수 | **페이지 개수에서 유도한 두수** | 이론값과 다를 때 | 행/열 누락·중복 |
| IC-5 | 페이지 원문 | `<!doctype html>` + 기대 캐션 | 지문이 없을 때 | 원본이 아닌 것 |

**IC-0은 정확성 검사가 아니다 (K6).** 원문이 동일하면 동일한 오파싱도 완전히
일치한다. IC-0이 배제하는 것은 파서의 비결정성과 위치 의존성뿐이다. 그리고
`_probe`와 `"1"`의 원문 동일성은 경주 한 건에서만 확인됐으므로, **파싱 전에
바이트 동일성을 먼저 검사하고 그 분포를 보고한다.** 원문이 다른 경주가
존재하면 IC-0의 적용 대상에서 제외하고 건수를 기록한다.

**IC-4의 B는 셀 파싱과 분리한다 (K5).** 두수를 같은 표의 마번 열이나 배당
존재 여부로 만들면, 행이 통째로 누락될 때 T와 B가 함께 줄어 검사가 통과한다.
대신 **`3Bc`/`3Both`의 페이지 키 개수**를 두수의 원천으로 쓴다. 이 값은
수집기가 마번 목록으로부터 만든 것이고 행렬 셀과 무관하다. Scm 계열 풀은
이 두수를 기준으로 검정한다. 페이지 키 개수와 마번 열 길이가 불일치하면
그 자체를 IC-4 위반으로 보고한다.

### 4.2 수집 메타 (보조 증거, 게이트 아님) (K4)

`meta`의 자체 검증 필드는 **수집기가 만든 것이므로 독립 검정이 아니다.**
게이트라고 부르지 않는다. 표시만 한다.

- `base_pages_match`, `has_required_betting_pages`, `missing_betting_pages`
- `base_page_checks.*`, `advanced_page_checks.*`
- `collection_attempts`, `retry_history`

### 4.3 KRA 표본 대조 (K1)

**독립성은 비교 기준 B를 어떻게 만드느냐에 달려 있다.** 재수집 페이지를 같은
v3 파서로 읽으면 체계적 매핑 오류가 양쪽에 재현되어 일치한다. 그러면 이 검정은
파서를 자기 자신과 비교하는 것이 된다.

따라서 **두 개의 비교를 모두 수행한다.**

**(a) 바이트 대조** — 재수집 HTML과 아카이브 HTML을 정규화 후 바이트 비교.
파서가 개입하지 않는다. 아카이브가 KRA 원문의 충실한 사본인지만 판정한다.
정규화 범위(세션 토큰, 타임스탬프, 광고 영역)는 사전에 고정하고 기록한다.

**(b) 독립 전사 대조** — 표본 중 **5경주**를 사람이 브라우저에서 눈으로 읽어
셀 값을 직접 표에 옆긴다. v3 파서를 쓰지 않는다. 이 전사본이 B다.

비교 대상은 **사전에 고정한다.** 각 경주에서:
- 7개 풀 전부
- 각 풀의 셀 전수 (표본이 작으므로 가능)
- 비교 좌표는 `(page_key, page_variant, row_header, col_header)`로 지정한다.
  `row_ord`/`col_ord`가 아니라 헤더 값으로 지정하는 것이 중요하다 — 순서가
  틀렸을 때 그것이 드러나야 하기 때문이다.

층화 표집 30–50 경주 (바이트 대조), 그중 5경주 (독립 전사):

| 층 | 이유 |
|---|---|
| meet 1·2·3 | 페이지 차이 |
| 2016 · 2018 · 2022 · 2025 | 개편, 2018 상한 해제 |
| 등록두수 ≤7 / 8–10 / ≥11 | 착순 규칙 경계 |
| 취소마 있음 | `----` 처리 |
| θ 인쇄 있음 | 검열 처리 |

**불일치가 0이 아니면 파서 또는 아카이브가 틀린 것이다.** (a)에서 불일치하면
아카이브 문제, (b)에서만 불일치하면 파서 문제로 나뉘다.

요청 예절: 초당 1건 이하, `User-Agent` 명시, 재시도 3회 상한.

### 4.4 포함·제외 규칙 (K4)

실패한 경주·풀을 어떻게 처리하는지 사전에 고정한다. **사후에 정하지 않는다.**

| 사유 | L1 | L2 진입 | 보고 |
|---|---|---|---|
| IC-5 실패 | 저장 안 함 | 불가 | 중단 조건 |
| 표 캐션 불일치 | 셀 저장, 캐션 원문 기록 | 해당 풀만 제외 | 건수 + 사유 |
| 이상 토큰 | `cell_raw` 보존, 변환값 `None` | 해당 셀만 결측 | 토큰별 건수 |
| IC-1/IC-4 위반 | 저장 | 해당 풀 제외 | 중단 조건 |
| 수집 메타 표시 | 저장 | **진입함** | 표시만 |
| 도착순서 없음 | 저장 | L2 적중 계산 불가 | 건수 |

**선택 효과 검사가 필수다.** 제외·결측이 연도·meet·등록두수·취소마 유무·
θ 인쇄 유무와 독립인지 교차표로 확인하고 `REPORT_P0.md`에 싣는다. 특정 층에
집중되면 그 자체를 보고한다.

## 5. 중단 조건과 임계 (K4, 7절)

**임계값은 실측 후에 정한다.** 근거 없는 숫자를 미리 박아두면 그것이 결론을
움직인다.

절차: 임계 없이 전 경주를 훑어 **분포를 먼저 측정**하고(`--survey` 모드),
그 분포를 근거로 임계를 정한 뒤 본실행한다. 임계와 그 근거는 7절 표에
기록한다.

측정 없이도 무조건 중단하는 것:

- IC-5 실패 1건 이상 (원본 지문 없음)
- IC-1 위반 1건 이상 (행/열 전치)
- 4.3(b) 독립 전사 불일치 1건 이상

이 셋은 "일부는 괜찮다"가 성립하지 않는 종류다.

## 6. 산출물

```
outputs/p0/
  raw_cells/        L1. 파티션: page_key / year / month
  derived/          L2 (골격만. 규칙은 SPEC_P0b)
  diagnostics/      L3
  lineage.csv       필드 계보표
  survey.json       임계 결정용 분포
  manifest.json     파티션별 행수·바이트·sha256
  REPORT_P0.md      결과
```

`REPORT_P0.md`에 반드시 포함할 것:

1. 경주 수, 행 수, **L1 산출물의 실측 총 크기**
2. IC-0 ~ IC-5 각각의 통과/실패 건수. IC-0은 원문 바이트 동일성 분포 포함
3. 이상 토큰 상위 200종과 빈도
4. 표본 대조: (a) 바이트 대조 결과, (b) 독립 전사 결과. 각각 표본 크기·비교 셀 수·불일치 수
5. 4.4 선택 효과 교차표
6. `warrant=없음`인 필드 목록
7. 중단 조건 근접도
