# SPEC_P0 — 데이터 검증

## 0. 이 단계의 목적

원시 아카이브에서 분석 가능한 표를 만들고, **그 표가 맞다는 것을 원본 없이
어떻게 아는지**를 확립한다.

두 번째가 핵심이다. 아카이브는 수집기 v3의 산출물이고, 그 이전 단계는 존재하지
않는다(OPEN_ITEMS #1). KRA 페이지 원문과의 일치는 재수집으로만 확인할 수 있다.

## 1. 확정된 전제

2026-08-11에 실물로 확인한 것들. 재논의 대상이 아니다.

| 항목 | 확인 내용 | 확인 방법 |
|---|---|---|
| 위치 | `<Dropbox>/kra-analysis/data/raw_collected_v3_15w/` | 전수 조회 |
| 구조 | `kra_YYYY/raw_archive/YYYY/YYYY-MM/YYYY-MM-DD_{meet}_{race}.json.gz` | 전수 조회 |
| 연도 | 2016–2019, 2022–2025 (2020–21 부재) | 폴더 목록 |
| 원문 | HTML 온전. `<!doctype html>`, `<table>` 존재 | `gunzip` 후 태그 계수 |
| 인코딩 | `<meta charset="euc-kr">` | 동일 |
| meet | 서울 1, 제주 2, 부산경남 3 | KRA 사이트 메뉴 |
| 페이지 | `Scm` `Both` `Bc` `3Bc`(마번별) `3Both`(마번별) | 파일 구조 |
| URL | 각 페이지의 원본 URL이 `urls`에 보존 | 파일 구조 |
| `_probe` | `3Bc`/`3Both`의 `_probe`는 `"1"`과 **완전 동일** | 문자열 비교 |

### 1.1 풀과 페이지의 대응

| 페이지 | 담긴 풀 | 표 형태 |
|---|---|---|
| `Scm` | 단승 · 연승 · 복승 | 단승/연승 열 + 마번 열 + 복승 상삼각 |
| `Bc` | 복연승 | 대칭 행렬 (상삼각만 유효) |
| `Both` | 쌍승 | 비대칭 행렬. **헤더가 `(후착 / 선착)`이므로 행=2착, 열=1착** |
| `3Bc` × 마번 | 삼복승 | 고정마 1 + 행/열 |
| `3Both` × 마번 | 삼쌍승 | **헤더가 `(3위 / 2위)`이므로 행=3착, 열=2착** |

## 2. 설계 원칙 — 파서는 판정하지 않는다

v1·v4 파서의 실패 8건 중 대부분이 파생 필드였다. 배당률 숫자를 읽는 부분은
멀쥰했고, 틀린 것은 전부 파서가 규칙으로 계산해낸 값이었다.

그러므로 세 층으로 나눈다.

| 층 | 산출물 | 하는 일 |
|---|---|---|
| L1 추출 | `raw_cells/` | HTML → 셀 값. **원문 그대로.** 판정 없음 |
| L2 규칙 | `derived/` | 도착순서 + 규정 → 적중, 지급 착순 수 |
| L3 진단 | `diagnostics/` | 검열, 이상 토큰, 정합성 위반 |

**L1은 무손실이어야 한다.** `9999.9`는 `9999.9`로, `-`는 `-`로, `----`는
`----`로 저장한다. 숫자로 변환하지 않고 문자열로 남긴다. L2·L3가 틀리면 L1을
다시 돌리지 않고 고칠 수 있어야 한다.

L1에 들어가서는 안 되는 필드: `is_hit`, `place_cutoff`, `is_capped`,
`is_valid`, `is_cancel`.

## 3. 파서 규칙 — 세 버전 대조

### 3.1 v1이 틀렸고 v4가 고친 것

| 규칙 | v1 | v4 | v3 |
|---|---|---|---|
| 지급 착순 수 | 유효두수 ≥8→3, ≥5→2 | 부분식별 `[lo,hi]` + `determinate` | L2에서 오버라운드 역산 |
| 복연승 적중 | 상위 `cutoff` 부분집합 | 항상 상위 3 | L2. 상수 근거 명시 |
| 검열 | `odds >= 9999.9` | `at_cap` / `above_cap` 분리 | L3. L1은 원문 보존 |
| 유효두수 | 단승 배당 있는 마번 | 등록두수 별도 보존 | L1이 마번 열 전체 보존 |
| 의존성 실패 | 맨몸 `except` | `import lxml` 최상단 | 동일 + 원본 지문 게이트 |

### 3.2 v4에 남은 것

**(a) `to_odds`의 느슨한 폴백.** v4는 이상 토큰을 카운터에 기록하되 여전히
`re.search`로 숫자를 뽑아낸다. `"1.5 취소"`가 `1.5`가 된다. **v3은 정확히
매칭되지 않으면 `None`**, 원문은 별도 컬럼에 보존, 이상 토큰 비율이 임계를
넘으면 중단.

**(b) `tables[0]`.** 페이지의 첫 표를 무조건 쓴다. 레이아웃이 바뀌어 표가
하나 추가되면 조용히 엉뚱한 것을 읽는다. **v3은 캐션으로 표를 식별한다.**
각 페이지의 표 캐션은 `출전번호별 ...의 배당률, 매출총액, 취소마를 제공하는 표`
형태이며, `...` 부분이 풀을 지정한다.

**(c) `_probe` 미해명.** v4는 건너뛰기만 한다. 1절에서 `_probe == "1"`임을
확인했으므로, **v3은 이를 검증에 쓴다**(4.1 IC-0).

## 4. 검증 — 세 층

파서가 맞는지를 원본 없이 판단해야 하므로, 서로 독립인 세 경로를 쓴다.

### 4.1 내부 정합성 (전 경주)

각 검사는 **실패 가능 조건**을 함께 적는다. 적을 수 없는 검사는 삭제한다.

| ID | 검사 | 실패 조건 |
|---|---|---|
| IC-0 | `_probe`와 `"1"` 페이지의 파싱 결과가 완전 일치 | 파서가 비결정적이거나 페이지 식별이 위치 의존적일 때 |
| IC-1 | 복승 행렬의 대각선에 마번, 하삼각은 전부 비값 | 행/열 정렬이 어긋날 때 |
| IC-2 | 삼복승 조합이 최대 3개 고정마 페이지에서 관측되고 값이 일치 | 셀 매핑이 틀렸을 때 |
| IC-3 | 도착마번이 등록 마번의 부분집합, 중복 없음 | 마번 추출이 틀렸을 때 |
| IC-4 | 각 풀의 조합 수가 두수로부터 계산한 이론값과 일치 | 행/열 누락 또는 중복 |
| IC-5 | 페이지에 `<!doctype html>`과 대상 캐션이 존재 | 원본이 아닌 것을 읽었을 때 |

IC-5가 원본 지문 게이트다. **2026-08-11에 연구자가 Dropbox 커넥터의 텍스트
추출본을 원본으로 오인한 사건**이 이 게이트를 만든 이유다. 문법적으로 멀쥰하고
배당률까지 읽히지만 원본이 아니었다.

### 4.2 수집 메타 게이트

`meta`의 자체 검증 필드를 게이트로 쓴다. 통과하지 못한 경주는 제외가 아니라
**표시**한다.

- `base_pages_match`, `has_required_betting_pages`, `missing_betting_pages`
- `base_page_checks.*`: `has_html`, `has_expected_date`, `has_expected_meet`,
  `has_expected_race_label`, `text_length`
- `advanced_page_checks.*`: `expected_detail_count` 대 `saved_detail_count`
- `collection_attempts`, `retry_history`

**주의:** 이 필드들은 수집기가 만든 것이다. 수집기의 버그를 수집기의 자체
검증으로 잡을 수는 없다. 보조 증거이지 독립 검정이 아니다.

### 4.3 KRA 표본 대조 (독립)

**이것만이 독립적이다.** `urls`로 표본을 재수집해 대조한다.

층화 표집 30–50 경주:

| 층 | 이유 |
|---|---|
| meet 1·2·3 | 페이지 차이 |
| 2016 · 2018 · 2022 · 2025 | 개편, 2018 상한 해제 |
| 등록두수 ≤7 / 8–10 / ≥11 | 착순 규칙 경계 |
| 취소마 있음 | `----` 처리 |
| θ 인쇄 있음 | 검열 처리 |

**불일치가 0이 아니면 파서가 틀린 것이다.** 결과를 표본 크기와 함께 보고하고,
불일치가 있으면 전면 재수집을 A형 부채로 승격한다.

요청 예절: 초당 1건 이하, `User-Agent` 명시, 실패 시 재시도 3회 상한.

## 5. 중단 조건

다음 중 하나라도 발생하면 실행을 멈추고 보고한다. 계속 진행해 부분 산출물을
남기지 않는다.

- IC-5 실패 (원본 지문 없음)
- Scm 표 추출 실패율 > 0.5%
- 이상 토큰 비율 > 0.1%
- IC-1 또는 IC-4 위반 1건 이상
- 표본 대조 불일치 1건 이상

## 6. 산출물

```
outputs/p0/
  raw_cells/        L1. 파티션: market / year / month
  derived/          L2
  diagnostics/      L3
  manifest.json     파티션별 행수·바이트·sha256
  REPORT_P0.md      결과
```

`REPORT_P0.md`에 반드시 포함할 것:

1. 경주 수, 행 수, **L1 산출물의 실측 총 크기**
2. IC-0 ~ IC-5 각각의 통과/실패 건수
3. 이상 토큰 상위 200종과 빈도
4. 표본 대조 결과: 표본 크기, 비교 셀 수, 불일치 수
5. 중단 조건 근접도

1번이 이후 작업 방식을 정한다. 수백 MB 이하면 클라우드 작업이 가능해지고,
수 GB면 로컬에 묶인다.

## 7. 상수

이 명세가 쓰는 수치 상수와 근거.

| 상수 | 값 | 근거 |
|---|---|---|
| θ | 9999.9 | v2가 측정으로 확인. θ의 점질량이 인접 구간 대비 34–111배 |
| Scm 추출 실패 임계 | 0.5% | **근거 없음.** P0 종료 전 결정 필요 |
| 이상 토큰 임계 | 0.1% | **근거 없음.** P0 종료 전 결정 필요 |
| 표본 크기 | 30–50 | **근거 없음.** 검출력 계산 필요 |

근거 없는 상수 3개가 남아 있다. **동결 조건 위반이며, P0 종료 전에 해소해야
한다.** 여기 적어두는 것은 비평자가 찾아내기 전에 저자가 먼저 인정하는 것이지,
면제가 아니다.
