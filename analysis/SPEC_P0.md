## 0. 이 단계의 목적

원시 아카이브에서 분석 가능한 표를 만들고, **그 표가 맞다는 것을 원본 없이
어떻게 아는지**를 확립한다.

두 번째가 핵심이다. 아카이브는 수집기 v3의 산출물이고, 그 이전 단계는 존재하지
않는다(OPEN_ITEMS #1). KRA 페이지 원문과의 일치는 재수집으로만 확인할 수 있다.

### 1.1 풀과 페이지의 대응

| 페이지 | 담긴 풀 | 표 형태 |
|---|---|---|
| `Scm` | 단승 · 연승 · 복승 | 단승/연승 열 + 마번 열 + 복승 상삼각 |
| `Bc` | 복연승 | 대칭 행렬 (상삼각만 유효) |
| `Both` | 쌍승 | 비대칭 행렬. **헤더 `(후착 / 선착)` → 행=2착, 열=1착** |
| `3Bc` × 마번 | 삼복승 | 고정마 1 + 행/열 |
| `3Both` × 마번 | 삼쌍승 | **헤더 `(3위 / 2위)` → 행=3착, 열=2착** |

### 1.2 특수 문자열의 의미 (r2-K6)

`analysis/p0_probe.py`로 측정했다. 각 측정은 **검사 대상이 되는 배당 셀 규칙이
건드리지 않는 부분**에서 근거를 가져온다. 배당 셀 자체를 읽어 의미를 정하면
검정 대상이 자기 근거를 공급하는 순환이 되기 때문이다.

| 문자열 | 판정 | 근거 | 규모 |
|---|---|---|---|
| `9999.9` (θ) | **우측 검열점.** 조합 부재·미출전·파싱 실패가 아님 | 같은 두 마리의 복연승 배당(다른 페이지·다른 풀)이 정상 숫자로 존재 | θ 셀 2,594건 / 581경주. 반례 0 |
| `----` | **출전취소** | 성적표 심판위원 리포트 (2018-08-19 부경 6R 3번 쇼트스톱, 열사병) + 취소마공지 행 대응 | 대응 2,163건, 불일치 20건 (0.1%) |
| `-` | **구조적 빈칸** | 위치로 판정 — 하삼각(중복조합) 또는 두수 초과 열(미출전) | 구조 확인 |
| 자유 텍스트 배당 토큰 | **존재하지 않음** | 전수 주사 | 0건 |

**θ 판정의 한계를 명시한다.** 측정이 배제하는 것은 θ가 조합 부재·미출전·파싱
실패의 표식이라는 가능성이다. θ 셀 2,594건 전부에서 같은 두 마리의 복연승
배당이 정상 숫자로 존재하며, 비교 기준이 그 자체로 θ인 경우는 0건이다. 나아가
그중 **1,174건(45.3%)은 쌍승 풀 내부의 역순 조합이 정상 배당을 갖는다** — 같은
경주, 같은 풀, 같은 두 마리다. 조합이 제공되지 않았거나 말이 뛰지 않았다면
반대 방향에도 배당이 붙을 수 없다.

배제되지 않는 것: **참배당이 유한하되 상한에서 잘린 것인지, 해당 순서에 베팅이
없어 미정의인지는 이 측정으로 구분되지 않는다.** 나머지 1,420건(54.7%)이
양방향 모두 θ라는 사실은 후자 쪽 무게를 실어주지만 확정하지 못한다.

이 미해결은 부분식별을 막지 않는다. 검열이면 참배당 ∈ [θ, ∞), 무베팅이면
참배당 = ∞이며, 어느 쪽이든 내재확률 ≤ 1/θ이다. 구분이 필요해지는 것은 점추정을
시도할 때이고 P0의 일이 아니다. `IDEAS.md` I1이 쓰는 상한은 두 해석 아래 동일하다.

**θ의 출현 분포 (2026-08-11 정정).** 이전 판본은 "주로 쌍승이다"라고 적었다.
**사실이 아니다.** 그 진술은 기초 페이지만 센 것이고, 고급 페이지를 넣으면
분포가 뒤집힌다.

| 범위 | θ 있는 경주 | θ 셀 |
|---|---|---|
| 기초 페이지 (`Scm`·`Both`·`Bc`) | **583 / 19,301 (3.0%)** | 2,618 |
| 전 페이지 (`3Bc`·`3Both` 포함) | **15,964 / 19,301 (82.7%)** | 3,913,364 |
| 고급 페이지에만 θ가 있는 경주 | 15,381 (79.7%) | — |

θ 셀의 **99.93%가 삼복승·삼쌍승 페이지에 있다.** 쌍승이 아니라 **삼쌍승이
θ의 주된 출현처다.** 조합 수가 훨씬 많고 배당이 크므로 상한에 닿는 셀이 많은
것으로 보이나, 그 해석은 아래대로 아직 검정되지 않았다.

**왜 이것을 놓쳤나.** `analysis/p0_probe.py`는 `Both` 격자에서 θ를 세고, 그
밖에는 **`Scm`과 `Bc`만** 검사했다(`for pk in ("Scm", "Bc")`). `3Bc`와 `3Both`는
θ 주사 대상이 아니었다. 위 두 줄은 `analysis/p0_sample.py`가 `_probe`를 제외한
전 페이지를 셀 단위로 다시 세어 얻은 것이며, 원자료는 `outputs/p0/strata.csv`의
`theta_cells_base`·`theta_cells_all` 열이다. 기초 페이지 수치는 `p0_probe.py`와
일치한다(쌍승 2,594셀 / 581경주, 차이 2경주는 복연승 θ).

**θ 판정의 적용 범위는 기초 페이지다.** 위 표의 비순환 대조 — 쌍승 θ를 복연승
배당과 맞대보는 것 — 는 기초 페이지에서만 수행됐다. **고급 페이지의 θ
3,910,746셀은 같은 검사를 거치지 않았다.** 그것들도 우측 검열점이라고 볼
근거는 현재 없으며, 있다고 가정하지도 않는다. `REPORT_P0.md`에 이 공백을
명시하고, 고급 페이지 θ에 대한 대조를 설계할지는 별도 판정 대상이다.

**복연승의 θ.** 복연승 θ는 위 대조의 비교 기준을 무효화할 수 있으나, 관측된
2건은 쌍승 θ 조합과 겹치지 않았다(위 표의 반례 0). **구조적으로 겹치지 않는
것이 아니라 이번 아카이브에서 겹치지 않았을 뿐이므로**, 재실행 시 비교 기준이
θ인 행을 별도로 세어 보고한다.

## 2. 설계 원칙 — 파서는 판정하지 않는다

v1·v4 파서의 실패 8건 중 대부분이 파생 필드였다. 배당률 숫자를 읽는 부분은
멀쩡했고, 틀린 것은 전부 파서가 규칙으로 계산해낸 값이었다.

| 층 | 산출물 | 하는 일 |
|---|---|---|
| L1 추출 | `raw_cells/` | HTML → 셀 값. **원문 그대로.** 판정 없음 |
| L2 규칙 | `derived/` | 도착순서 + 규정 → 적중, 지급 착순 수 |
| L3 진단 | `diagnostics/` | 검열, 이상 토큰, 정합성 위반 |

L1에 들어가서는 안 되는 필드: `is_hit`, `place_cutoff`, `is_capped`,
`is_valid`, `is_cancel`.

### 2.1 L1 스키마 — 좌표를 보존한다 (r1-K3)

값 문자열만 보존하는 것으로는 무손실이 아니다. 행/열 매핑이 틀렸을 때 L1을
다시 돌려야 하기 때문이다. **셀의 출처 좌표를 함께 저장한다.**

`raw_cells/` 한 행 = 페이지의 한 셀. 각 필드의 출처는 2.2 계보표에 있다.

| 컬럼 | 형 | 내용 |
|---|---|---|
| `race_id` | str | `YYYY-MM-DD_{meet}_{race}` |
| `page_key` | str | `Scm` `Both` `Bc` `3Bc` `3Both` |
| `page_variant` | str | 고정마 번호 또는 `_probe`. 단일 페이지는 빈 문자열 |
| `table_ord` | int | 페이지 내 표의 등장 순서 |
| `table_caption` | str | 표 캡션 원문 (표 식별의 근거) |
| `row_ord` | int | 표 내 행 순서 (0부터) |
| `col_ord` | int | 표 내 열 순서 (0부터) |
| `row_header` | str | 행 머리 셀의 원문 |
| `col_header` | str | 열 머리 셀의 원문 |
| `cell_raw` | str | **셀 원문 그대로.** 변환·정규화 없음 |
| `rowspan` `colspan` | int | 병합 셀 정보 |

`cell_raw`는 `9999.9`, `-`, `----` 무엇이든 원문 그대로다. 숫자 변환은 L3의
일이다.

이 스키마면 행/열 해석이 틀렸을 때 `row_ord`/`col_ord`만 다시 매핑하면 되고,
HTML을 다시 읽지 않는다.

### 2.2 필드 계보 (r1-K2, r2-K1)

**모든 산출 필드는 계보표에 한 행을 갖는다.** 계보표가 없는 필드는 산출물에
존재할 수 없다.

컬럼 정의: `field` 필드명 / `layer` L1·L2·L3 / `origin` `direct`(원천 직접
판독) 또는 `derived`(규칙 계산) / `source` direct면 원문 좌표, derived면 입력
필드 목록 / `rule` derived면 생성식 / `warrant` 그 규칙이 참인 근거 —
`규정` · `문서` · `측정` · **`없음`**.

`warrant`가 `없음`인 파생 필드는 **동결 조건 위반**이다. 아래 표를
`outputs/p0/lineage.csv`로 산출하고 `REPORT_P0.md`에 요약한다.

#### L1

| field | origin | source | rule | warrant |
|---|---|---|---|---|
| `race_id` | direct | 아카이브 JSON 최상위 `race_id` | — | 측정 (구조 전수 확인) |
| `page_key` | direct | `pages` 딕트의 키 | — | 측정 (구조 전수 확인) |
| `page_variant` | direct | `pages["3Bc"]`·`pages["3Both"]`의 하위 키. URL의 `chulNo1` 파라미터에 대응 | — | 측정 (`urls`와 대조) |
| `table_ord` | derived | 페이지 HTML | 페이지 내 `<table>` 등장 순서, 0부터 | 측정 |
| `table_caption` | direct | 해당 `<table>`의 `<caption>` 텍스트 | — | 측정 (전수 12종, 3.2(b)) |
| `row_ord` | derived | 표 HTML | 표 내 `<tr>` 등장 순서, 병합 전개 후 | 측정 |
| `col_ord` | derived | 행 HTML | 행 내 `<td>`·`<th>` 등장 순서, 병합 전개 후 | 측정 |
| `row_header` | **derived** | `row_ord`, 표 구조 | 해당 행의 첫 머리 셀 텍스트 | 측정 |
| `col_header` | **derived** | `col_ord`, 표 구조 | 머리 행에서 `col_ord` 위치의 셀 텍스트 | 측정 |
| `cell_raw` | direct | `(table_ord, row_ord, col_ord)` 위치의 셀 텍스트 | — | — |
| `rowspan` `colspan` | direct | 셀의 HTML 속성 | — | — |

**`row_header`·`col_header`가 `direct`가 아니라 `derived`인 것이 중요하다
(r2-K1).** 이 둘은 "행 머리 셀"이라는 **위치 규칙**의 산물이다. 그런데 4.3(b)는
순서 의존을 피하려고 비교 좌표를 헤더 값으로 잡는다. 헤더 자체가 위치 규칙에서
나오므로 그 독립성은 부분적이다. 이 구멍은 4.3(b)의 좌표 부재 조항으로 막는다.

#### L3

| field | origin | source | rule | warrant |
|---|---|---|---|---|
| `cell_value` | derived | `cell_raw` | 숫자 정규식에 **정확히** 매칭될 때만 float. 아니면 `None` | 측정 (자유 텍스트 토큰 0건) |
| `cell_class` | derived | `cell_raw`, **`page_key`**, `row_ord`, `col_ord`, 두수 | 아래 여섯 값 중 하나 | 아래 |
| ├ `numeric` | | | 숫자 정확 매칭이고 θ 아님 | — |
| ├ `censored_at_theta` | | | `cell_raw == "9999.9"` **이고 `page_key` ∈ {`Scm`, `Both`, `Bc`}** | 측정 (1.2). **기초 페이지에 한함** |
| ├ `theta_printed` | | | `cell_raw == "9999.9"` **이고 `page_key` ∈ {`3Bc`, `3Both`}** | 측정 — **문자열 일치까지만.** 검열이라는 근거는 없음 |
| ├ `cancelled` | | | `cell_raw`가 `----` | 문서 + 측정 (1.2) |
| ├ `structural_blank` | | | `-`이고 위치가 하삼각 또는 두수 초과 | 측정 (1.2) |
| └ `unknown_token` | | | 그 외 전부 | — |
| `meta_selfcheck_present` | direct | `meta`에 `has_required_betting_pages` 키가 있는지 | — | 측정 (4.2) |
| `probe_bytes_identical` | derived | `pages`의 `_probe`와 `page1` 바이트열 | 동일 여부 | 측정 |

**`unknown_token`은 관측 0건이지만 클래스를 유지한다.** 재수집이나 다른
연도에서 나타날 수 있고, 그때 조용히 `None`으로 흡수되지 않아야 한다.

**θ가 두 클래스로 갈라진 이유 (2026-08-11).** 1.2의 비순환 대조는 기초
페이지에서만 수행됐다. 고급 페이지의 θ 3,910,746셀 — 전체 θ의 99.93% — 은 같은
검사를 거치지 않았다. 그것을 `censored_at_theta`로 분류하면 **측정하지 않은
것을 측정한 것처럼 적는 것**이 된다.

**해결은 warrant를 비우는 것이 아니라 주장을 줄이는 것이다.** `theta_printed`가
주장하는 바는 "그 자리에 `9999.9`가 인쇄되어 있다"뿐이고, 그것은 문자열 일치로
확인된다. 따라서 이 클래스의 warrant는 `없음`이 아니며 동결 조건을 위반하지
않는다. **위반이 되는 것은 근거 없이 `censored_at_theta`로 부르는 쪽이다.**

| 무엇을 | 근거 |
|---|---|
| 고급 페이지에 `9999.9`가 인쇄되어 있다 | 측정 (문자열 일치) |
| 그것이 우측 검열점이다 | **없음** |
| 그것으로 내재확률 상한 1/θ를 쓸 수 있다 | **없음** |

아래 두 줄에 근거가 생기기 전까지 **고급 페이지 θ를 배당값으로도, 검열
표식으로도 쓰지 않는다.** 4.4가 L2 진입을 막고, 8절이 이 판정을 P0 범위 밖으로
둔다. 근거가 생기면 `theta_printed`를 `censored_at_theta`로 승격하고 계보표의
warrant를 갱신한다 — 그 전에는 두 클래스를 합치지 않는다.

**이것은 r2-K6이 기각한 `at_cap`/`above_cap` 구분의 부활이 아니다.** 그 구분은
같은 셀에 대해 *검열이냐 미정의냐*라는 **의미**를 갈랐고, 1.2가 구분 불가능하다고
판정했으므로 삭제됐다. 여기서 갈리는 것은 의미가 아니라 **근거의 유무**이며,
기준은 페이지 계열이라는 관측 가능한 사실이다. 고급 페이지 θ 안에서 검열과
미정의를 나누지 않는 것은 기초 페이지와 동일하다.

#### L2

| field | origin | source | rule | warrant |
|---|---|---|---|---|
| 지급 착순 수 | derived | — | **SPEC_P0b** | **없음** |
| 적중 여부 | derived | — | **SPEC_P0b** | **없음** |

L2의 핵심 파생 필드는 **P0에서 확정하지 않는다.** 오버라운드 역산의 정확한
형태와 근거는 별도 명세를 요구하며, P0의 산출물은 그 규칙을 적용할 수 있는
`derived/` 자리와 계보표 골격까지다. **이 상태로는 P0가 종료되지 않는다.**

## 3. 파서 규칙 — 세 버전 대조

### 3.1 v1이 틀렸고 v4가 고친 것

| 규칙 | v1 | v4 | v3 |
|---|---|---|---|
| 지급 착순 수 | 유효두수 ≥8→3, ≥5→2 | 부분식별 `[lo,hi]` | L2. 규칙은 SPEC_P0b |
| 복연승 적중 | 상위 `cutoff` 부분집합 | 항상 상위 3 | L2. 규칙은 SPEC_P0b |
| 검열 | `odds >= 9999.9` | `at_cap` / `above_cap` | L3 `censored_at_theta` 하나 |
| 유효두수 | 단승 배당 있는 마번 | 등록두수 별도 보존 | L1이 마번 열 전체 보존 |
| 의존성 실패 | 맨몸 `except` | `import lxml` 최상단 | 동일 + IC-5 |

**v4의 `at_cap`/`above_cap` 구분을 채택하지 않는다 (r2-K6).** 1.2에서 두 상태를
구분할 수 없다고 판정했으므로, L3에 그 구분을 남겨두면 근거 없는 분류를 만드는
것이 된다. `censored_at_theta` 하나로 합친다.

### 3.2 v4에 남은 것

**(a) `to_odds`의 느슨한 폴백.** v4는 이상 토큰을 기록하되 `re.search`로 숫자를
뽑아낸다. **아카이브 전수에서 그런 토큰은 관측되지 않았다**(1.2). 그럼에도 v3은
L1에서 변환하지 않는다 — 폴백은 원문을 잃는 구조 자체가 문제이고, 재수집본이나
미수집 연도에서 처음 나타날 때 조용히 숫자로 바뀌면 안 되기 때문이다. 변환은
L3에서 하고, 정확히 매칭되지 않으면 `None` + `cell_raw` 보존 +
`cell_class=unknown_token`.

**(b) `tables[0]`.** v3은 `table_caption`으로 표를 식별한다. 캡션은
`출전번호별 ...의 배당률, 매출총액, 취소마를 제공하는 표` 형태이며 `...`이
풀을 지정한다. 기대 캡션이 없으면 IC-5 실패. 전수에서 관측된 캡션은 12종이며
`outputs/p0/odd_tokens_top200.csv`에 있다.

**(c) `_probe`.** 4.1 IC-0 참조.

## 4. 검증

파서가 맞는지를 원본 없이 판단해야 하므로, 서로 다른 경로를 쓴다. **독립성의
정도가 다르며, 그 차이를 명시한다.**

### 4.1 내부 정합성 (전 경주)

각 검사는 **검정 대상 T**, **검정 기준 B**, **실패 가능 조건**을 함께 적는다.
B의 계산에 T 또는 T를 만든 규칙이 들어가면 순환이며 삭제 대상이다.

| ID | T | B | 실패 조건 | 무엇을 배제하는가 |
|---|---|---|---|---|
| IC-0 | `_probe` 파싱 결과 | `"1"` 파싱 결과 | 두 결과가 다를 때 | **비결정성과 위치 의존성만.** 정확성은 배제하지 못함 |
| IC-1 | 복승 행렬의 대각·하삼각 패턴 | 표 형태 규정 | 행/열 정렬이 어긋날 때 | 행/열 전치 |
| IC-2 | 삼복승 조합의 페이지 간 값 | 서로 다른 고정마 페이지의 같은 조합 | 값이 불일치할 때 | 셀 매핑 오류 |
| IC-3 | 도착마번 집합 | 등록 마번 집합 | 부분집합이 아니거나 중복일 때 | 마번 추출 오류 |
| IC-4 | 각 풀의 관측 조합 수 | 페이지 키 개수에서 유도한 두수 | 이론값과 다를 때 | **파싱 단계의** 행·열 누락·중복 |
| IC-4b | 페이지 키 개수 | Scm 표의 마번 열 길이 | 두 값이 다를 때 | 수집기 N과 KRA 표의 불일치 |
| IC-5 | 페이지 원문 | `<!doctype html>` + 기대 캡션 | 지문이 없을 때 | 원본이 아닌 것 |

**IC-0은 정확성 검사가 아니다 (r1-K6).** 원문이 동일하면 동일한 오파싱도 완전히
일치한다. IC-0이 배제하는 것은 파서의 비결정성과 위치 의존성뿐이다. **파싱 전에
바이트 동일성을 먼저 검사하고 그 분포를 보고한다.** 2018년 300경주에서 동일이
확인됐으나 다른 연도로 일반화하지 않는다. 원문이 다른 경주가 존재하면 IC-0의
적용 대상에서 제외하고 건수를 기록한다.

**IC-4는 수집 단계의 누락을 배제하지 못한다 (r2-K2).** 이전 판본은 IC-4가
행·열 누락 일반을 배제한다고 썼다. 그 주장을 철회한다.

IC-4의 B인 페이지 키 개수는 수집기가 두수 N으로부터 만든 것이고, **N의 출처는
아카이브에 남아 있지 않다.** 수집기 v3의 코드도 이 기기에 없다. 아카이브에서
확인되는 것은 페이지 키가 예외 없이 `1..N` 연속이라는 사실뿐이며, 이는 N 하나로부터
기계적으로 생성됐음을 보일 뿐 N이 어디서 왔는지는 말해주지 않는다. N이 Scm
페이지에서 유도됐다면 T와 B가 함께 축소되는 공통 실패 경로가 열려 있고,
아카이브 내부 검사로는 그 경우를 배제할 수 없다.

**남는 것 둘.** 첫째, IC-4는 **파싱 단계**의 행·열 누락·중복은 여전히 배제한다.
T는 셀에서 나오고 B는 페이지 키에서 나오므로 파서가 행을 흘리면 T만 줄어든다.
둘째, IC-4b — 마번 열은 KRA가 서빙한 Scm HTML에서 오고 페이지 키 개수는 수집기
N에서 오므로, **N이 Scm에서 유도된 경우가 아니라면** 수집기의 마번 누락은 여기
걸린다.

**수집 단계 누락의 검출 책임은 4.3(a) 바이트 대조로 넘긴다.** 재수집 HTML과
아카이브 HTML을 비교하면 수집 단계 누락이 파서를 거치지 않고 드러난다. 이것이
아카이브 내부에서 답할 수 없다는 사실의 유일한 귀결이다. OPEN_ITEMS #2에 등재한다.

### 4.2 수집 메타 (보조 증거, 게이트 아님) (r1-K4, r2-K5)

`meta`의 자체 검증 필드는 **수집기가 만든 것이므로 독립 검정이 아니다.**
게이트라고 부르지 않는다. 표시만 한다.

- `base_pages_match`, `has_required_betting_pages`, `missing_betting_pages`
- `base_page_checks.*`, `advanced_page_checks.*`
- `collection_attempts`, `retry_history`

**측정 결과 (표본 600경주, 전 연도).**

| 사실 | 규모 |
|---|---|
| `missing_betting_pages`가 비어있지 않은 경주 | **0건** |
| `has_required_betting_pages` 필드 자체가 없는 경주 | **100건 / 600** |
| 필드 유무와 연도·경마장·수집기 버전의 관계 | 무관 |
| `raw_status` | 전수 `saved` |

**필드가 없는 것은 "통과"가 아니라 "검사되지 않음"이다.** 이 구분이 4.4의 포함
규칙을 가른다. 100/600은 표본에서 나온 수치이며 **전수 비율이 아니다.** 본실행
때 전수로 다시 세어 `REPORT_P0.md`에 싣는다.

### 4.3 KRA 표본 대조 (r1-K1, r2-K4, r2-K7)

**독립성은 비교 기준 B를 어떻게 만드느냐에 달려 있다.** 재수집 페이지를 같은
v3 파서로 읽으면 체계적 매핑 오류가 양쪽에 재현되어 일치한다. 그러면 이 검정은
파서를 자기 자신과 비교하는 것이 된다.

따라서 **두 개의 비교를 모두 수행한다.**

**(a) 바이트 대조** — 재수집 HTML과 아카이브 HTML을 정규화 후 바이트 비교.
파서가 개입하지 않는다. 아카이브가 KRA 원문의 충실한 사본인지만 판정한다.
정규화 범위(세션 토큰, 타임스탬프, 광고 영역)는 **재수집 실행 전에** 고정하고
`outputs/p0/normalize_rules.md`에 커밋한다.

**(b) 독립 전사** — 5경주를 사람이 브라우저에서 눈으로 읽어 셀 값을 직접 표로
옮긴다. v3 파서를 쓰지 않는다. 이 전사본이 B다.

#### 표본 크기와 추출 규칙 (r2-K7)

이전 판본은 4.3에서 30–50, 7절에서 미정이라고 적어 모순이었다. r2-K7 반영본은
**40**으로 통일했다. 실측 후 **38로 확정한다 (2026-08-11).**

38은 검출력 계산에서 나온 수가 아니다. 불일치율의 사전 추정치가 없어 검출력
계산이 불가능하다. **38은 아래 층 설계에서 나온 수이며, 표본 크기가 설계를
따르지 설계가 표본 크기를 따르지 않는다.**

층:

| 층 | 이유 |
|---|---|
| meet 1·2·3 | 페이지 차이 |
| 2016 · 2018 · 2022 · 2025 | 개편, 2018 상한 해제 |
| 등록두수 ≤7 / 8–10 / ≥11 | 착순 규칙 경계 |
| 취소마 있음 | `----` 처리 |
| θ 인쇄 있음 | 검열 처리 |

**정원 계산 — 34칸이지 36칸이 아니다.**

앞의 세 층(meet · 연도 · 등록두수)을 교차하면 3 × 4 × 3 = **36칸**이고, 칸당
1경주다. 나머지 두 층(취소마 있음 · θ 인쇄 있음)은 커버리지 요구이며 각 2경주다.

**그런데 36칸 중 2칸이 비어 있다.** 2025년 서울(meet 1)과 부경(meet 3)에
등록두수 7두 이하 경주가 **한 건도 없다**(`outputs/p0/strata.csv` 전수 계수).
없는 칸에서는 뽑을 것이 없으므로 교차는 34칸이 된다.

| 항목 | 수 |
|---|---|
| 설계된 교차 칸 | 36 |
| 비어 있는 칸 | 2 (meet1/2025/≤7, meet3/2025/≤7) |
| 뽑을 수 있는 칸 × 1 | **34** |
| 커버리지 층 2개 × 2 | **4** |
| **표본** | **38** |

**빈 칸을 메우는 안은 전부 기각한다.** 빈 칸 몫을 다른 칸에 주는 안, 연도 층을
빼는 안, 등록두수 경계를 옮겨 칸을 채우는 안. 층은 검사 목적에 맞춰 정한 것이고
(≤7은 착순 규칙이 갈리는 경계), 그것을 데이터 사정으로 바꾸면 **r2-K3이 지적한
사후 자유도**가 된다. 빈 칸은 데이터의 사실이므로 그대로 둔다. 산출물에도
정원 0으로 남겨 "왜 34칸인가"가 파일만 보고 드러나게 한다.

**불일치 0건일 때 말할 수 있는 것.** 이항 단측 95% 상한 1 − 0.05^(1/38) =
**0.0758**, 즉 **불일치율이 약 7.6% 미만**이라는 것뿐이다. (40이었다면 7.2%였다.)
이 문장을 `REPORT_P0.md`에 그대로 싣고 **그 이상을 주장하지 않는다.**

**추출은 결정론적이다.** 각 층에서 `sha256(race_id)`를 오름차순 정렬해 상위
k개를 뽑는다. 난수 종자도, 사람의 선택도 개입하지 않는다. 층별 정원과 뽑힌
38개의 `race_id` 목록을 **재수집 실행 전에** `outputs/p0/sample_38.json`으로
커밋한다.

**독립 전사 5경주는 같은 해시 순서의 상위 5개로 미리 정한다.** 바이트 대조
결과를 보기 전이다. 결과를 본 뒤 전사 대상을 고르는 여지를 없애기 위해서다.

#### 전사 절차 (r2-K4)

이전 판본은 "v3 파서를 쓰지 않는다"만 규정하고, 전사자가 파싱 결과에 노출되는
것을 막지 않았다. 그러면서 (b)의 불일치를 곧바로 파서 문제로 귀속했다. 세
단계를 추가한다.

1. **차단.** 전사 담당자는 해당 5경주의 `raw_cells/` 산출물과 어떤 파싱 결과도
   보지 않는다. 전사가 파싱보다 **시간상 앞서면** 가장 깨끗하며, 그 순서를
   커밋 타임스탬프로 남긴다.
2. **봉인.** 전사본은 비교 **전에** `outputs/p0/transcript/`로 커밋한다. 커밋된
   후에는 수정하지 않는다. 수정이 필요하면 새 파일로 추가하고 사유를 적는다.
3. **원인 판정.** 불일치가 나오면 자동으로 파서 문제로 귀속하지 **않는다.**
   전사자와 별개의 사람이 원 브라우저 표시를 다시 확인해 셋 중 하나로 판정한다
   — 사람 전사 오류 / 파서 오류 / 원문 자체의 모호성. 판정 근거(어느 화면의
   무엇을 보았는지)를 `REPORT_P0.md`에 적는다.

#### 비교 대상

**사전에 고정한다.** 각 경주에서 7개 풀 전부, 각 풀의 셀 전수. 비교 좌표는
`(page_key, page_variant, row_header, col_header)`로 지정한다. `row_ord`/`col_ord`가
아니라 헤더 값으로 지정하는 것이 중요하다 — 순서가 틀렸을 때 그것이 드러나야
하기 때문이다.

**전사본에 있는 좌표가 L1에 없으면 그 자체를 불일치로 센다 (r2-K1).**
`row_header`·`col_header`는 위치 규칙의 산물이므로(2.2), 헤더 추출이 틀리면
좌표가 서로 어긋난다. 좌표가 없는 셀을 비교 대상에서 조용히 빼면 헤더 추출
오류가 침묵한다. 양쪽 좌표 집합의 대칭차를 전부 불일치로 보고한다.

**불일치가 0이 아니면 파서 또는 아카이브가 틀린 것이다.** (a)에서 불일치하면
아카이브 문제, (b)에서만 불일치하면 파서 또는 전사 문제이며 위 3단계로 나뉜다.

요청 예절: 초당 1건 이하, `User-Agent` 명시, 재시도 3회 상한.

### 4.4 포함·제외 규칙 (r1-K4, r2-K5)

실패한 경주·풀을 어떻게 처리하는지 사전에 고정한다. **사후에 정하지 않는다.**

| 사유 | L1 | L2 진입 | 보고 |
|---|---|---|---|
| IC-5 실패 | 저장 안 함 | 불가 | 중단 조건 |
| 표 캡션 불일치 | 셀 저장, 캡션 원문 기록 | 해당 풀만 제외 | 건수 + 사유 |
| `unknown_token` | `cell_raw` 보존, 변환값 `None` | 해당 셀만 결측 | 토큰별 건수 |
| **`theta_printed`** (고급 페이지 θ) | `cell_raw` 보존, `cell_value=None` | **해당 셀만 결측.** 배당값으로도 검열 표식으로도 쓰지 않는다 | 셀 수 + 경주 수 + 페이지별 내역 |
| IC-1 / IC-4 / IC-4b 위반 | 저장 | 해당 풀 제외 | 중단 조건 |
| 도착순서 없음 | 저장 | L2 적중 계산 불가 | 건수 |

**`theta_printed`를 결측으로 두는 것이 보수적인 쪽이다 (2026-08-11).** 삼복승·
삼쌍승 셀의 상당수가 여기 해당하므로(θ 셀의 99.93%), 이 규칙은 두 풀의 L2
가용 셀을 크게 줄인다. 그럼에도 이렇게 두는 이유는, 근거 없이 검열로 분류하면
**결측이 아니라 틀린 값**이 L2에 들어가기 때문이다. 결측은 세어서 보고할 수
있고 틀린 값은 그럴 수 없다. **줄어든 규모 자체를 `REPORT_P0.md`에 싣는다** —
그것이 고급 페이지 θ 대조를 설계할 가치가 있는지 판단하는 근거가 된다.

**수집 메타는 세 상태로 나눈다 (r2-K5).**

| 메타 상태 | L1 | L2 진입 | 보고 |
|---|---|---|---|
| 필드 있음 · `missing_betting_pages` 빔 | 저장 | 진입 (IC 통과 조건) | 건수 |
| 필드 있음 · 목록 비어있지 않음 | 저장 | **해당 풀만 제외** | 건수 + 풀별 내역 |
| 필드 없음 (미검사) | 저장 | 진입 (IC 통과 조건) | 건수 + `meta_selfcheck_present=false` |

세 상태 모두에서 **진입 판정은 IC-1~IC-5가 한다.** 메타 필드의 유무를 진입
조건으로 쓰면, 4.2가 "게이트가 아니다"라고 못박은 수집기 자기신고를 사실상
게이트로 승격시키는 것이 된다. 같은 이유로 필드가 없는 경주를 제외하지도 않는다.

**가운데 줄은 관측 0건인 채로 규칙만 고정한 것이다.** 표본 600에서 목록이
비어있지 않은 경주는 없었다. 관측이 없다고 규칙을 비워두면 나중에 한 건
나왔을 때 사후 결정이 되고, 그것은 5절이 막으려는 자유도와 같은 종류다.

**선택 효과 검사가 필수다.** 제외·결측이 연도·meet·등록두수·취소마 유무·
θ 인쇄 유무·**`meta_selfcheck_present`**와 독립인지 교차표로 확인하고
`REPORT_P0.md`에 싣는다. 마지막 축을 넣는 이유는, 메타 필드가 없는 경주가
특정 층에 몰려 있다면 그 자체가 수집기 동작의 신호이기 때문이다.

**"θ 인쇄 유무" 축은 두 개로 나눈다 (2026-08-11).** 기초 페이지 기준은 583경주
(3.0%), 전 페이지 기준은 15,964경주(82.7%)로 규모가 27배 다르다(1.2). 하나로
적으면 어느 쪽인지 정해지지 않고, 후자는 대부분의 경주가 한 칸에 몰려 교차표가
아무것도 가르지 못한다. **두 축을 따로 세운다** — `has_theta_base`와
`has_theta_all`이며, 둘 다 `outputs/p0/strata.csv`에 이미 있다.

## 5. 중단 조건과 임계 (r1-K4, r2-K3)

**임계값은 실측 후에 정한다.** 근거 없는 숫자를 미리 박아두면 그것이 결론을
움직인다. 그러나 "분포를 보고 정한다"만으로는 관측된 실패 규모를 허용하는
임계를 고를 자유도가 남는다. **분포에서 임계로 가는 결정 규칙을 survey 실행
전에 고정한다 (r2-K3).**

### 5.1 결정 규칙 — survey 실행 전에 커밋

Scm 추출 실패에 적용한다.

1. 실패율이 **0이면** 통과.
2. 0보다 크면, 실패가 층(연도 · meet · 등록두수 · 취소마 유무)에 대해 균등한지
   교차표로 판정한다. **특정 층에 집중되면 규모와 무관하게 중단한다** — 구조적
   결함이며 "몇 건뿐"이 성립하지 않는다.
3. 균등하면 실패 건수를 전수 목록화한다. 목록이 **200건 이하면** 전수를 육안
   확인한 뒤 진행하고, 초과하면 중단한다.

200은 검출력 기준이 아니라 **사람이 전수 확인 가능한 상한**이다. 4.3(b)의
5경주와 같은 종류의 근거이며, 그 사실을 `REPORT_P0.md`에 적는다.

**순서를 기록한다.** 이 규칙의 커밋이 `outputs/p0/survey.json` 생성보다 시간상
앞서야 한다. 두 커밋 해시와 타임스탬프를 `REPORT_P0.md`에 나란히 싣는다. 순서가
뒤바뀌면 이 절 전체가 무효이며, 그 사실도 적는다.

### 5.2 이상 토큰 임계 — 해당 없음

이전 판본은 이 임계를 "미정"으로 두었다. **미정이 아니라 해당 없음으로
확정한다 (r2-K6).** 아카이브 전수에서 자유 텍스트 배당 토큰은 0건이고, 빈도 50
이상인 토큰 12종은 전부 표의 열 머리다(1.2, `outputs/p0/odd_tokens_top200.csv`).
임계를 걸 대상이 존재하지 않는다.

`unknown_token`이 1건이라도 나타나면 그것은 임계 문제가 아니라 **전수 측정과
모순되는 관측**이므로 개별 조사 대상이다. 건수와 원문을 전부 보고한다.

### 5.3 측정 없이도 무조건 중단하는 것

- IC-5 실패 1건 이상 (원본 지문 없음)
- IC-1 위반 1건 이상 (행/열 전치)
- 4.3(b) 독립 전사 불일치 1건 이상 **중 원인 판정이 "파서 오류"로 난 것**

이 셋은 "일부는 괜찮다"가 성립하지 않는 종류다. 세 번째에 원인 판정을 붙인
것은 4.3(b) 3단계 때문이다 — 사람 전사 오류까지 중단 조건으로 삼으면 검사가
스스로를 막는다.

  manifest.json         파티션별 행수·바이트·sha256

`REPORT_P0.md`에 반드시 포함할 것:

1. 경주 수, 행 수, **L1 산출물의 실측 총 크기**
2. IC-0 ~ IC-5 각각의 통과/실패 건수. IC-0은 원문 바이트 동일성 분포 포함
3. `cell_class` 분포. `unknown_token`은 원문 전수. **`theta_printed`로 인해
   L2에서 빠지는 셀 수와 그것이 삼복승·삼쌍승의 몇 %인지** (4.4)
4. 표본 대조: (a) 바이트 대조, (b) 독립 전사. 각각 표본 크기·비교 셀 수·
   불일치 수·좌표 대칭차·원인 판정 내역. **불일치 0일 때 말할 수 있는 상한**
5. 4.4 선택 효과 교차표 (`meta_selfcheck_present` 축 포함)
6. `warrant=없음`인 필드 목록
7. 5.1 결정 규칙 커밋과 `survey.json` 생성의 시각 순서
8. 수집 메타 세 상태의 **전수** 건수
9. 중단 조건 근접도

**1번은 이후 작업 방식(로컬 vs 클라우드)의 결정 근거이지 연구 설계의 근거가
아니다.** 크기가 크다고 분석 범위를 줄이거나 표본을 자르지 않는다. 이 경로를
막기 위해 명시한다.

## 8. 이번 단계에서 하지 않는 것

- 배당률의 경제적 해석
- 오버라운드·공제율 추정
- θ의 검열/미정의 구분 (1.2. 부분식별에는 불필요)
- **고급 페이지 θ의 의미 판정** — 아래
- L2 규칙의 확정 (SPEC_P0b)
- 어떤 가설도 세우지 않는다

**고급 페이지 θ를 P0에서 판정하지 않는 것은 유보이지 방치가 아니다.** 1.2의
대조에 대응하는 비순환 검사가 삼복승·삼쌍승에 존재하는지는 조사 대상이다.
**그 조사는 L1 산출 이후로 미룬다 (2026-08-11 결정).** 지금 하면 정규식으로
HTML을 다시 훑는 일이 되고, `raw_cells/`가 좌표와 함께 셀을 표로 내주면 같은
조사를 더 싸고 정확하게 할 수 있다. 파싱 전에 할 일이 아니다.

**판정 전까지 고급 페이지 θ는 `theta_printed`로 남으며 L2에 들어가지 않는다**
(2.2, 4.4). 이 상태로는 θ 상수(7절)의 적용 범위가 기초 페이지에 한정되므로,
**아카이브 전체에 대해 내재확률 상한을 주장할 수 없다.** 그 제약을
`REPORT_P0.md`에 적는다.
